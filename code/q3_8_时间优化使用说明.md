# 问题三：方案三少架次解的时间优先优化

团队统一编号入口现为 `q3_6.py`，说明见 `q3_6_时间优化使用说明.md`；本文件保留原求解入口及历史运行参数说明。

在 PyCharm 中运行同目录的 `q3_8_time_optimize.py`。工作目录设为当前 `code` 文件夹；“脚本形参”可留空。默认以已验收的方案三少架次表为起点，搜索预算 1200 秒，目标是所有运输机和中继机最晚在第 7200 秒返回 O01。搜索预算不包含读取 DEM、初始验收和最终出表出图时间。

运行前用当前项目的 Python 环境安装 `requirements.txt`。特别需要 OR-Tools；若控制台提示缺少 `ortools`，在 `code` 目录运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

如需先试运行，在 PyCharm 的“脚本形参”填写：

```text
--time-budget-s 120 --max-rounds 3 --local-seconds 25 --global-seconds 40
```

完整搜索可直接清空形参运行。若想延长搜索，把 `--time-budget-s 2400` 填入脚本形参即可；它是计算预算，不是期望返航时间。`--target-s 7200` 才是两小时目标值。默认每三轮尝试一次全程重排；G0、G1、G2 分别将能耗和软延期相对方案三起点的容许增长固定为 0%、5%、10%，所有物理和硬时限约束均不放松。

从上一次已验收时间优化解继续搜索时，设置 `--warm-table <上次的 q3_time_*_table 文件夹> --grades G2 --time-budget-s 1200`。软指标的 10% 上限仍按最初方案三少架次解计算，不会随着续跑逐轮放大。续跑表和原方案三表必须对应相同的源数据。

程序输出到 `3_outputs/8_time/q3_time_时间戳_table` 和对应 `_figure`。查看 `Q3_运行摘要.json` 的 `final_metrics.makespan_s`、`target_gap_s`、`target_reached`、`improved_from_scheme3`；`Q3_时间目标比较.csv` 给出起点与本次最好解的四项原始指标。`Q3_时间优化搜索轨迹.json` 区分求解状态与独立验收状态；`Q3_READY.txt` 只在完整验收 PASS 后生成。

`target_reached=false` 只表示本次有限候选和限时搜索尚未找到两小时内的完整可行解，不是原题不可行的证明。若要指定输入，使用 `--scheme3-table` 和 `--data-run`；两者必须来自同一版原始数据。
