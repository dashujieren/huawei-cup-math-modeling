# 第四问基线：固定第三问任务后的分区与资源配置

依据《2026华为杯D题_建模执行思路_V1.0.pdf》内页第 12 页（文件标题 V3.0）的 4.1、4.2、4.4 节，以及官方题面问题四。文件沿用仓库的编号规则：`q4_0_baseline.py` 是基线入口，`q4_1_baseline_test.py` 是检查文件，结果默认保存在 `code/4_outputs/q4_base_时间戳_table/`。

## 需要的第三问输入

先完成并核验第三问。在同一个目录放置以下 UTF-8 CSV：

| 文件 | 必备列 | 来源 |
| --- | --- | --- |
| `Q3_运输架次.csv` | 架次编号、机型编号、开始时刻（s）、访问服务区顺序、返回O01时刻（s）、架次能耗（kWh） | 第三问运输补表，列名沿用 Q2_运输架次 |
| `Q3_逐箱交付.csv` | 货箱编号、架次编号、服务区编号、交付完成时刻（s） | 第三问逐箱补表，列名沿用 Q2_逐箱交付 |
| `Q3_中继架次.csv` | 中继架次编号、开始时刻（s）、建链完成时刻（s）、服务结束时刻（s）、返回O01时刻（s）、架次能耗（kWh） | 官方 Q3_中继架次 |
| `Q3_通信保障.csv` | 运输架次编号、开始时刻（s）、结束时刻（s）、中继架次编号 | 官方 Q3_通信保障；直连行的中继架次编号留空 |

第三问若已固定实体资源编号，运输表还应包含“无人机编号”“电池编号”，中继表还应包含“中继无人机编号”“能源组件编号”。四类编号须全部提供或全部省略。全部提供时，程序另算“沿用原编号、跨组复制”的保守配置，并复核同一编号的占用区间不重叠。

第三问独立验收通过后，在同一目录放 `Q3_READY.txt`。没有该标记时仍可试算，但第四问不会生成 `Q4_BASE_READY.txt`。这个标记本身不能替代第三问的飞行、时限和连续通信验证。

## 运行

在 `D题` 目录执行：

```powershell
.\code\.venv\Scripts\python.exe .\code\q4_0_baseline.py --q3-dir '第三问四张CSV所在目录的实际路径'
.\code\.venv\Scripts\python.exe -m pytest .\code\q4_1_baseline_test.py -q
```

也可用 `--data-run` 指定已验收的数据处理目录，用 `--output-dir` 指定新的结果目录；已有输出目录不会被覆盖。

## 算法和结果口径

1. 同一运输架次访问的服务区并为原子块；一个中继架次保障的运输架次所涉及服务区也并入同一块。中继架次不跨组复制。少于三个原子块时，明确报告无法分为三组，需返回第三问选择可分的联合方案。
2. 对 K=2、K=3 各自按块内箱数降序、最小服务区编号升序排序。前 K 块各占一组，其余逐块加入当前箱数最少的组；平局取组号小者。
3. 保持第三问架次、时刻、访问顺序和中继服务关系不变。运输机从准备开始占用至返航；中继机占用至返航后 300 s 周转结束。电池与中继组件占用至返航后按附件两段充电规则充满。事件扫描使用半开区间，求每组各类资源峰值，再对组求和。
4. `Q4_分区配置_基线.csv` 的 11 列与官方模板 `Q4_分区配置` 完全对应。另输出原子块、各组工作量、任务归组、资源占用区间、资源汇总及库存缺口原因。超过库存时如实列出缺口；“计算通过”不代表库存足够。

令 `I(j,r)=[s(j,r),e(j,r))` 为任务 `j` 对资源类型 `r` 的完整占用区间，`g(j)` 为固定任务归属组。组内最少需求为 `d(g,r)=max_t Σ_{j:g(j)=g} 1[t∈I(j,r)]`；分组独立总需求为 `D(r)=Σ_g d(g,r)`。库存缺口为 `max(0,D(r)-stock(r))`，库存冗余为 `max(0,stock(r)-D(r))`。相邻区间在同一时刻首尾相接时可复用同一资源。

本脚本不会代替第三问求解，也不会把模拟测试里的任务当作比赛结果。真实的 K=2/3 数值只能在第三问固定任务表到位后生成。
