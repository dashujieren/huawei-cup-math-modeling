# 第三问：固定第二问计划的通信中继基线

此脚本按题目与建模思路 PDF 的基线口径，固定已验收的第二问方案 5，不重排运输。先重放 19 个运输架次的爬升、巡航、下降和投送轨迹，再按双向链路预算与 DEM 找直连盲段，用有限网格和贪心安排 R01/R02 及能源组件。输出只代表此基线，不代表第三问全局可行性或最优性。

## 运行

在 `code` 目录选用已安装 `requirements.txt` 的 Python 解释器：

```powershell
python -m pip install -r requirements.txt
python q3_0_baseline.py
```

运行后会在 `3_outputs/0_baseline/q3_base_<时间戳>_table/` 写四张官方关联表、盲段/资源/区间验收和 `Q3_运行摘要.json`；同时间戳的 `_figure/` 存 PNG/PDF 图。可用 `--data-run`、`--q2-dir`、`--output-root` 指向明确输入或输出。默认选择与固定 Q2 源清单哈希一致的最新 PASS 数据运行。可用 `--sample-step-s` 和 `--shortlist-size` 调整搜索预算；这些只影响启发式搜索，不放宽最终验收。

只读复核现有表：

```powershell
python q3_0_baseline.py --validate-only "3_outputs/0_baseline/q3_base_<时间戳>_table"
```

单元测试：

```powershell
python -m pytest -q q3_1_baseline_test.py q3_2_validate_test.py q3_3_resources_test.py
```

## 如何理解结果

- `PASS`：四张表、资源与连续通信独立复核通过，才会有 `Q3_READY.txt`。此时第四问可用 `--q3-dir` 指向该 `_table` 目录。
- `BASELINE_UNCOVERED`：固定运输计划与当前有限候选贪心未覆盖全部通信区间。表中的“未覆盖”行仅供诊断，不能当正式可行结果交给第四问。
- `UNVERIFIED`：未找到反例，但保守的全区间链路证明不足；采样点通过不等于全时段通过。
- `ERROR`：输入版本、资源物理或输出关联复核不一致，需要先检查诊断。

`Q3_逐区间验收.csv` 给出分段证书或反例；`Q3_通信问题.json` 给出未覆盖、失败、未证实的定位信息。失败不证明第三问整体无解；可能需要更密候选或允许与第二问运输联合重排。
