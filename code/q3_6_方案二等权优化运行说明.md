# 第三问：以师兄方案二为起点的等权优化

在 PyCharm 打开并运行 `q3_6_scheme2_equal_optimize.py`。脚本形参可以留空；默认搜索预算为 600 秒。推荐解释器是本 `code/.venv/Scripts/python.exe`。Git 仓库副本中的 `0_outputs` 因换行转换不能通过文件哈希验收时，脚本会自动使用同步工作目录中的已验收数据。

本脚本不覆盖师兄的 `q3_2_optimize.py` 或原方案二输出。默认起点是 `3_outputs/2_optimize/` 下最新的 PASS 表格；新输出写入 `3_outputs/3_scheme2_equal/`。如果要指定起点，可在“脚本形参”填写 `--scheme2-table <方案二_table目录>`；指定时长可填写 `--time-budget-s 1200`。

四项指标为软箱加权迟到、最晚返航时刻、运输加中继总能耗、运输加中继总架次。分别除以师兄方案二的对应值后等权平均，记为 F；方案二 F=1。新方案必须独立通过运输、连续通信和中继资源验收，且 F<当前最好解，才被接纳。运输架次可多于 31；物理容量、硬截止和资源约束仍严格保留。

查看输出表格目录中的 `Q3_运行摘要.json`、`Q3_等权方案比较.csv`、`Q3_等权搜索轨迹.json` 与 `Q3_READY.txt`。`improved_from_scheme2=false` 表示当前预算内没有找到更优 PASS 解，输出仍为师兄原方案二。`global_optimality_proven=false` 表示没有证明全局最优。

已完成的一轮 600 秒正式搜索保存在 `3_outputs/3_scheme2_equal/q3_scheme2_equal_260925_153335_015378_table`：`PASS`，F=0.984637，30 次运输＋11 次中继。加权迟到比方案二高 6.968%，但最晚返航低 4.918%、能耗低 3.544%、总架次低 4.651%。重新运行可能因并行搜索而得到不同可行解；以各次输出中的 PASS 验收和 F 为准。

命令行示例（在 `code` 目录下）：

```powershell
.\.venv\Scripts\python.exe q3_6_scheme2_equal_optimize.py --time-budget-s 600
```
