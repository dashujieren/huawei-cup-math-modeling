# 问题三方案五设计：联合返航截止压缩与中继换班重构

日期：2026-09-25。状态：设计完成；本轮只读取既有输出、做表内时序诊断并制定方案，未修改求解代码、未运行新一轮优化。下述目标值是实验阈值，尚无方案五成绩。

## 1. 目标和时间口径

用户希望下一轮重点改善最晚返航和总时间。沿用已经确认的题意：任务从时刻0开始，运输架次开始包括工位准备；交付按交接完成记时；联合任务完成时刻取全部运输机和中继机返回O01的最晚时刻。距离、DEM、飞行能耗、充电、周转、链路与连续通信认证保持同一物理口径。

定义：

- C_T = max_p return_p：运输最晚返航，s。
- C_R = max_r return_r：中继最晚返航，s。
- C = max(C_T,C_R)：联合最晚返航，也是本轮“总任务完成时间”的主口径。
- D = max_b delivery_b：最后一箱交接完成时刻，s；不能代替返航完成。
- W_T = sum_p(return_p-start_p)，W_R = sum_r(return_r-start_r)，W=W_T+W_R：累计无人机任务占用时间，单位为机·s，可换成机·h。包括任务内准备、装载、交接、飞行、建链和悬停；不计返航后的充电和中继周转，也不计架次之间停在基地的空闲。后两项单列资源统计。

C是主目标。W作为次级目标和诊断，回答是否减少总工作量；并行的17机·h绝不是任务需要运行17小时。把C_T、C_R、C重复相加会重复计量，本轮不这样设目标。运行程序的墙钟时间另报，不与作业时间混用。

硬约束保持：80箱恰交付一次、箱不可拆分、载重与体积、逐段能量和返航安全余量、8架运输机与14组电池、2架中继机与6组组件、充电和周转不冲突、医疗及首批保障硬截止、合法站点与双向链路、全过程零通信缺口。架次数是决策结果，不固定为24、26或9。

### 2.3 中继工作量解释了为什么还需改结构

若固定这9个中继任务的持续时间，允许在2架中继机间重新分配，忽略其他限制，则：

`C >= [16984.288397 + (9-2)*300] / 2 = 9542.144198 s`。

只计每架机最后任务之前必需的周转，返航后最后一次周转不计入C。此为固定9个任务时长的条件下界，不是Q3全局下界。energy与lateness相同口径的条件界分别为10100.195795、9900.706553秒。

## 4. 数学模型与两级目标

运输候选p含货箱集合B_p、访问顺序、机型、时长d_p、能耗e_p、逐箱交付偏移以及相对通信盲段。变量为是否选择x_p、开始t_p和资源分配。逐箱恰一次覆盖：`sum_{p:b in B_p} x_p = 1`。

中继候选任务r选择站点j、实体机及组件；决策开始s_r、建链完成q_r、服务结束h_r及返回v_r。沿用当前准备、往返、建链和耗电公式：`q_r=s_r+prep+out_j+setup`，`v_r=h_r+home_j`。

运输盲段k相对开始为[a_pk,b_pk]。分配给中继r时，站点必须认证可覆盖完整区间，且`q_r<=t_p+a_pk`、`h_r>=t_p+b_pk`。一个中继可同时保障多架运输机；不能把盲段运输并发数直接当成中继需要量。

联合返航：所有选中运输的`t_p+d_p<=C`，所有启用中继的`v_r<=C`。W_T为所选运输时长之和，W_R为启用中继的`v_r-s_r`之和。

**第一阶段最小化C**，同时给E、L、Nt和总架次设透明的实验上限，全部物理与资源约束保持。不能把不同量纲直接相加。

**第二阶段在所得时间上界内最小化W**，再按E、L筛选非支配代表解。只称“在已找到时间水平上优化累计机时”，第一阶段未证明最优时不宣称严格字典序全局最优。累计机时不能完全包含排程等待收益，因此仍要分列D与L。

### 4.1 更紧的时间域与数值映射

- 对每个兼容种子先重建其模型可行时刻，使用该模型的返航上界收紧时间域。不能只把物理10124.682直接写成10124的整数界。
- 被选路线开始上界同时取：返航上界减完整时长、该路线各硬截止减交付偏移的最小值；按当前整数刻度保守取整。
- 电池最终充电、最后一次中继周转可发生在C之后。对“返航时间域”与“资源释放/充满时间域”分别设界，不能因为缩短C而强迫全部电池在C前充满。
- 保留完整资源先后约束。缩短h_r会改变能耗、SOC与组件充电时间，须同步重算，不能只改一列结束时间。
- 整数模型与真实时刻的差显式记录；按导出的物理结果重验C、E、L及硬截止。现有0.218秒硬余量不能靠额外容差放过。

### 4.2 实验阈值和状态解释

先直接最小化C并更新可行上界；停滞时可检验`C<=10000、9800、9600秒`，逐次使用上一个可行解作提示。若进展支持，再试更低阈值。与当前10124.682相比，它们分别要求再缩短约2分05秒、5分25秒、8分45秒。

某个限时阈值返回UNKNOWN，只说明未获结论。有限候选模型INFEASIBLE，只能排除同一批候选、档位和固定条件下的该阈值；换站点、机型、组批后失效。不做把UNKNOWN当无解的二分搜索，也不把局部模型的界跨轮继承为全局下界。

## 5. 具体优化动作

### A. 三个起点与候选路线共享

以低延期解为主起点：它和fast一样快，硬截止最小余量122.5秒。保留fast的较低能耗/较短中继占用结构，以及energy的24批次结构作为独立起点。

导入各自完整表和验收，提取三套已用路线，合成精确覆盖的初始候选池。原任务编号只用于各自诊断。互换路线时用80箱恰一次约束阻止重叠或漏箱；不能直接拼接两份调度表。每个种子先有一次固定自身批次、放开全部时刻/资源/中继的时间求解，然后竞争更新候选池。

### B. 共享服务窗口与中继换班顺序一起调整

从当前终点回溯紧约束与近紧约束，区分运输机、运输电池、中继机、组件、通信窗口及硬截止。优先释放整条相关链；共享窗口关联的邻域外任务仍保留覆盖约束，必要时扩大邻域。

第一批候选围绕fast的R004—R006—R008及其关联运输展开，并在其他种子上重新识别对应链：

1. 调整两架中继机的任务分工、先后顺序及组件分配，不固定原资源编号。
2. 对时间可相容且有共同覆盖点的运输需求尝试集中服务，使R006一类长窗口更紧凑。所谓“服务波次”只用于候选生成，不把波次写成额外硬约束。
3. 对两个中继共享的运输任务，尝试重新分配通信区间，提前释放关键机；其他服务义务必须同时得到保障。
4. 比较持续悬停、合并窗口与拆成两次的完整代价。拆分新增准备/往返/建链/300秒周转，合并增加悬停能耗，都须完整排程。
5. 必要的交接切换须在覆盖已认证的区间端点进行，前后窗口无缝；不能以删掉未覆盖端点来缩短任务。

### C. 在最新收尾结构上细化站点

当组批或换班顺序改变后，立即重新识别末班需求并补充有价值的站点。围绕R008类尾部点、其服务航段及共同覆盖走廊，按250m、100m、50m逐级细化；只有有潜力的局部区域进入下一档。离地高度沿用合法档位，并对有优势点适度细化。

同时评估全区间接入与回传、去程时间、回程时间、转场能耗、最大服务时长及链路余量。对末班任务，较短回程可能直接缩短C；对前驱任务，较短去回程可提前释放中继机。不能只按覆盖数最多或海拔最高选点。

原用站点始终保留。覆盖集合相同也不能仅凭往返总时间删除候选：去程较短、回程较短分别影响不同紧约束，应分别比较。先以相同路线/相同预算做旧池与新池对照，记录新站点是否实际被用到。

### D. 末班与前驱货箱、机型联合重组

对S002末班6箱，允许与较早同区批次移箱、交换、拆分，比较A/B/C可行机型；也放开相邻B/C任务，避免只是把S002提前而让其他区成为更晚的尾巴。硬箱始终满足原截止，不能为了给软箱腾位置推迟医疗或首批保障。

沿关键链生成换型、移箱、两批交换、两批/三批重组、必要的单批拆分与双区顺序替换。不固定“运输越少越好”，也不指定A型一定接手；逐条核算载重、体积、能量、通信和资源周转。

初始释放6—10个关联运输任务；停滞则扩大至12—18个。至少安排一次所有现选批次的整体重排，可改变资源先后顺序和中继结构。路线池控制在约120—180个活动选项，局部可扩至240；优先保留三种原解和已验收改进解使用的路线。站点活动池约40—60个，必要时扩至80。上述数值是计算预算，不是原题限制。

Nr不固定为9；运输和中继分别计数，总架次界显式约束。60秒只是额外安全余量实验，不是题面硬性规定；0秒与60秒的结果分别标记。R原解已满足60秒，主分支有真实可行起点。若F、Q不满足主分支L或余量，不强制其全部任务进入该分支；其路线可以作为可选候选。

建模前检查必选路线数、箱覆盖、档位指标和取整可映射性。记录SEED_INCOMPATIBLE/INVALID_HINT与SOLVER_INFEASIBLE不同状态。候选只有完整验收且达到对应真实界才进入正式档案。

档案保留(C,W,E,L,Nt,Nr)非支配结果；硬截止余量作为额外筛选。运行期间保留全部原参考解。没有时间改善时如实输出“本轮未改善C”，其他指标改善另报。

## 7. 预算、进度与可恢复性

默认30分钟优化预算，可配置；数据重建、几何预计算、独立验收和出图耗时单列。第一版预算建议：固定批次与多种子对照约20%，换班/窗口重构约35%，站点及货箱重组约30%，同C下累计机时整理约15%。几何新增与局部认证也须有独立时限，不能在求解预算外无限生成候选。

- 单次局部模型约60—90秒；优质新结构立即获得120—240秒全程时间求解，实际取剩余预算允许值。
- 使用动态剩余预算，避免累计阶段截止把新起点剥夺了时间；未用预算转交有效分支。
- 初始每类结构动作至少尝试一次，再按“单位求解时间内的已验收C改善”分配，保留少量探索机会。无改善不等同于证明最优。
- 连续一轮完整动作覆盖仍无改善，先扩大邻域/换种子/针对最新尾部改点；多次覆盖仍停滞可提前停止并记录原因。不能只把固定5轮写死，也无需无意义耗满预算。
- 每个阶段和每次新可行解显示进度、已用/剩余预算、C_T/C_R/C、当前目标、实际档位、释放数、站点数、下界的适用模型。求解器长时间无新解时仍给心跳，保证用户知道正在求解。
- 每次验收通过的有价值方案保存完整checkpoint：货箱/路线、所有时刻、资源编号、站点坐标与物理属性、区间分配、输入/代码/候选池哈希、参数、求解状态和界。异常中断保留最后可行方案。

数据指纹不一致禁止复用认证；缓存仅加速，不决定默认候选池。记录独立stage字段，防止基础求解器report覆盖外层阶段名称。

## 8. 实验与验收

用同一数据、物理口径和已记录预算比较：

1. 原方案四三个代表解。
2. 仅增加全程时间求解预算的对照，区分新设计收益与算得更久。
3. 在2上加入紧时间域、三种子候选共享和换班/窗口重构。
4. 在3上加入针对新尾部的站点细化。
5. 在4上加入关键链货箱/机型重组与小幅权衡。
6. 在最佳C水平上整理W，并比较0/60秒额外余量。

各阶段实际运行才填数据；同一候选在不同阶段重复出现只记实际来源。主表分列C_T、C_R、C、D、W_T、W_R、E_T、E_R、L、Nt、Nr、最小硬余量、软迟到箱数、通信缺口和程序耗时。旧方案可从完整表补算W；缺文件的项写“未复算”，不得填0。

独立验证从导出的原始精度表重算80箱、完整轨迹/能耗/交付、各类实体资源与充电周转、站点和全区间通信。额外反例检查：

- 调早T024却让其原共享中继与其他任务冲突；
- 缩短窗口后未更新组件充电时间；
- 边界上一段结束早于下一段建链，留下小于采样步长的缺口；
- 将最后充电或最后周转误计为C；
- 26条必选路线与24运输上限同时存在；
- 仅靠模型取整容差让真实硬截止或能耗越界；
- 改变候选池却继续沿用旧模型下界；
- 同一T编号在不同方案对应不同货箱而被错误合并。

只有完整PASS且全部原题硬约束满足才能写READY。保留原数据精度后再作展示舍入。该问题仍是有限候选下的联合调度搜索；OPTIMAL最多说明相应整数候选模型，不能直接称原题连续空间全局最优。
